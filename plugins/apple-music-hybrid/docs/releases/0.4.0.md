# Groovectl 0.4.0

This is a prepared public-source candidate and private plugin update. GitHub/npm publication and public plugin-directory submission remain separate release steps.

## Changes

- Optional inspiration across 13 questions with 205 prebuilt choices, up to six visible at a time. Fresh host-agent choices use the existing saved-brief tool. Locks persist; seen-option history avoids immediate repeats within a session.
- Pick for me, More ideas, Fill in the blanks and Reroll unlocked ideas. Randomization preserves original intent and hard policies. Host agents reconcile generated inspiration with natural-language constraints.
- Codex and experimental agy CLI image adapters, plus optional BYOK OpenAI, Gemini and OpenRouter. Explicit provider/model snapshots, one image per job, local rolling attempt caps, 429 cooldowns, durable request deduplication and no paid fallback.
- PNG/JPEG outputs with actual MIME, immutable image resources, dashboard display and export. Richer prompts incorporate sound/context and deliberate visual direction.
- Three cohesive preference/library tools: get_music_preferences, preview_music_change and apply_music_change. Ratings have before-state/readback checks and partial-progress journals. Favorites/library additions remain accepted/unverified after 202, with no replay.
- Updated agent skill, interview examples, setup guides and capability map. Existing tool names, private data and plugin identity remain compatible. There are 50 tools, without separate tools per question or provider.
- Release dependency metadata matches the frozen lockfile; UI builds use the root's pinned packages instead of retained legacy UI dependencies.

## Qualification

TypeScript checks/build and 67 tests passed on macOS; Windows passed 66 with one POSIX symlink test skipped. Both SDK 1 and SDK 2 stdio clients discover 50 tools and exercise interviews and PNG/JPEG image/resource/UI contracts, including an isolated Windows package. The original 14 Python regression tests passed. The skill validator passed. A real authenticated Apple ratings read succeeded without changing preferences. Desktop light and 390-pixel phone dark layouts were inspected through the MCP Apps synthetic host; locks, rerolls, fresh agent choices and provider routing were exercised without real music writes.

The native helper source is unchanged from the prior four-test/release-build checkpoint. This release does not establish fresh installed-helper, interactive Windows SMTC or authenticated Cider qualification.

Codex image generation has real macOS direct/worker evidence from 0.3.1. The agy trial finished with no image and a denied command; agy remains experimental pending local permissions/image availability. BYOK adapters have simulated request/response/budget/error coverage, with no charged live API calls. Music preference/library writes have contract coverage, not permission to change the user's taste for testing. Apple RatingRequest's typed object and one endpoint example disagree about type spelling; this implementation follows the typed object and records live write qualification as pending.

Cover upload/application, arbitrary saved-playlist reorder/entry removal, mixed API library/catalog write references and useful folder organization remain open. Prioritize those coherent workflows and actual player qualification rather than adding wrappers merely to increase tool count.
