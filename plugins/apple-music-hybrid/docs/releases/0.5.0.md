# Groovectl 0.5.0 candidate

The [first public preview](https://github.com/justinthevoid/groovectl/releases/tag/v0.5.0) is published, following private development versions. It includes CLI/plugin/source archives, checksums and a qualification manifest for public commit 30da56bd456499aa658252e764501a5cd663f97e. npm registry and public plugin-directory publication remain separate and unpublished. Source and tarball installation are documented in the README.

## What is ready to try

- Exact recording discovery, catalog and personal-library exploration, Apple-provided alternatives, charts, recommendations and eligible Replay data.
- Reviewed playlist creation/additions, mixed catalog and API-library recordings, folder organization, snapshots and exports. Accepted and uncertain writes retain their receipts and cannot silently repeat.
- Listening stories: chapters, pinned recordings, preserved album runs, runtime budgets and six recipe guides. The sequencer retains every recording and reports unsatisfied constraints.
- Optional interviews with more than 200 starting points, host-agent suggestions, locks, surprise and reroll. A clear natural-language request needs no interview.
- Original PNG/JPEG cover generation through configured Codex CLI, experimental agy, or explicit OpenAI/Gemini/OpenRouter BYOK. One attempt per request, local caps, no automatic paid fallback. Exporting a cover does not apply it to Apple Music.
- A profile-aware playlist studio in MCP Apps and OpenAI Extensions, plus ordinary MCP tools for other hosts. API-only Linux/VPS operation does not advertise desktop playback.
- An Astro 7/Svelte 5/Starlight website, self-hosted assets/fonts, Cloudflare Static Assets configuration and an unprivileged VPS static-site deployment. Headless music access remains private stdio over SSH.

## Qualification

The final portable source passed type/UI checks and bundle builds on Linux and Windows. Linux passed 104 tests; Windows passed 103 with one POSIX-only symlink test skipped. SDK 1 and 2 clients are exercised in the suite. Earlier macOS source passed 101 tests and 14 historical Python regressions; the final bundle's macOS smoke is recorded separately in the qualification ledger.

The production Codex artwork worker generated a real 1024-square cover using an existing ChatGPT login in isolated storage. The public Between Stations example includes provenance. No charged BYOK call was used for release qualification.

The release process also checks unpacked npm/plugin packages, embedded app resources, headless persistence, source/archive privacy and dependency notices. See [the current qualification ledger](../qualification.md) for completed receipts and exact scope, rather than inferring live platform behavior from these checks.

## Known limits

Interactive Windows Apple Music, authenticated Cider, live folder placement/mixed-reference writes and charged BYOK generation remain unqualified. agy returned no image in its bounded live trial and stays experimental. The API does not offer complete playlist editing or a documented custom-cover upload route; removal/reordering of arbitrary existing playlists is not claimed. Replay is the latest eligible year, not complete listening history. No audio analysis is invented when BPM/key/energy are absent.

Public CI passed four hostless Swift tests, the release helper build, app packaging and strict ad hoc signature verification. No notarized/prebuilt helper is distributed. Source installs retain the native gate and require the operator's normal macOS permissions; desktop Automation/runtime and notarization remain separate qualification tasks.

The current dashboard browser checks use a synthetic MCP Apps development host. They do not establish live account writes or the final installed ChatGPT host's rendering. OpenAI directory submission is a separate review, with local-executor requirements made explicit.

## Operator upgrade

Back up the complete private data directory and any external MusicKit key before replacing an installation. Keep it private and encrypted. Use the checked release tarball with `npm install --prefix "$HOME/.local/share/groovectl" --ignore-scripts /path/to/groovectl-0.5.0.tgz`, or install from a frozen source checkout as described in the README. Keep legacy launch aliases and plugin identity when upgrading an existing private installation.

Run `groovectl doctor` and read capabilities in a fresh MCP process. Upgrade code without replacing journals or copying old database files over newer ones. Inspect an accepted/unknown operation instead of replaying it. Roll back the code only when its storage format remains compatible; a backup restore is an operator decision, not an automatic retry.
