# Groovectl 0.5.2 qualification checkpoint

This patch includes 0.5.1's compact studio responses and closes defects found during release qualification. It adds no tools or dependencies and preserves journal and write-safety contracts.

- Workspace lists contain plan/draft summaries. Existing inspectors retrieve complete saved recordings, receipts, constraints and suggestions. The installed Node 24 CLI's measured workspace fell from 205,059 to 3,338 UTF-8 bytes (98.4%).
- Windows studio controls follow the live session rather than the adapter's potential capabilities. Late saved-brief responses preserve new typing and navigation. Cider accepts documented empty `204` responses; missing timestamps remain unknown.
- The headless smoke now verifies both the summary and complete selected brief after process replacement. It caught a stale full-draft assumption during the first public CI run; the check was corrected without weakening the persistence assertion.

Clients that previously read `get_music_workspace.plans[].payload` should use `inspect_playlist_plan(plan_id)` for full details. `get_playlist_studio.drafts[]` is a summary list; request `draft_id` and read `draft` for the full saved brief. Mutation results and stored journal schemas are unchanged.

See the [qualification ledger](../qualification.md) for the actual source, package, host and player receipts. Desktop refresh and expanded-host rendering are separate from saving a private plugin release. No paid image request, account preference change, new queue item or library write is part of this checkpoint.
