# 0.6.0-rc.4 candidate

The player now names its execution host and offers supported local Apple Music and Cider adapters. Switching reads state without starting playback or changing the saved CLI default. Existing playback/queue tools accept an optional `player`; the full profile remains 52 tools.

Failed switches clear old controls, mismatched/late responses cannot select another player, and profile/API-only restrictions remain authoritative. Cider setup status is distinct from connection readiness. Queue reads follow the selected adapter. Each release has a distinct app resource URI to avoid sharing an old HTML identity with a newly negotiated release.

The [platform guide](../platforms.md#connect-the-windows-extension) explains Windows-local execution. Opening a Mac-backed chat on a Windows screen does not move the player connection. Windows playback does not require copying MusicKit credentials.

Automated, synthetic browser, installed-host and live-player checks have separate scopes in the [qualification ledger](../qualification.md). Windows SMTC metadata and Cider queue limitations remain at their recorded scope until separately verified. npm, directory publication, notarized helper distribution and a public docs hostname retain the [distribution gates](0.6.0-rc.2.md#distribution-gates).
