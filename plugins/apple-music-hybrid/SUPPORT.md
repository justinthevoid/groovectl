# Support

Read the install/MusicKit/platform guides, run groovectl --version and groovectl doctor, and check the qualification ledger. Use doctor --probe only when you intend to contact the selected player.

For a bug, include CLI version/commit, Node version, operating system, selected backend, expected/observed behavior and a synthetic reproduction. Redact home paths, account IDs, playlist names and listening data. Never upload the private data directory, .p8 key, tokens, raw environment or unredacted logs. Security reports belong in the private channel described in SECURITY.md.

Use repository issues for reproducible bugs, documentation gaps and concrete feature requests. There is no guaranteed support SLA. Explain the listening/operating task a feature would improve; a missing API wrapper alone is not a reason to add a tool.

An uncertain write should be inspected using its saved plan and the real library. Do not repeatedly apply, delete the journal, or create a replacement plan to force a retry. Include only a redacted state/receipt summary when asking for help.
