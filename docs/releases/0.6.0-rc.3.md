# 0.6.0-rc.3 candidate

This candidate addresses a reported library-read failure and inability to start a song. It preserves the 52-tool interface, plugin identity, local setup, journals and music-write rules.

- Fix Music.app title/artist searches using its documented search-area enum. The previous `songs` value caused an Apple Event type-conversion failure; `all` searches the native library without changing recording identities.
- Recover one transient Apple API GET failure within the original 25-second deadline. Connection/body failures with recognized transient codes and HTTP 502/503/504 qualify. Authorization errors, rate limits, unknown failures and expired deadlines do not retry; account writes never replay.
- Distinguish an empty native resume from starting a selected recording, with an actionable error. API browsing and desktop playback remain separate connections and ID namespaces.

The [qualification ledger](../qualification.md) separates the actual panel observation, successful direct Apple reads, native search/playback and automated regressions. The reported API timeout was observed in the panel but did not recur during direct reads; these changes do not establish its original network cause. Actual panel interaction remains a live gate.

Source/CLI/plugin distribution checks qualify this candidate separately. npm publishing, public directory eligibility, notarized helper distribution and a public docs hostname retain the [existing distribution gates](0.6.0-rc.2.md#distribution-gates). Saving a private plugin update does not publish it publicly.
