# 0.6.0-rc.2 candidate

This source candidate extends the Collection browser with shuffle/repeat controls, a phone seek bar and recovery fixes. It preserves existing tool names, private journals, plugin identity and reviewed-write behavior. Packaging or private installation does not publish an npm package or a public plugin listing.

## Changes

- Use observed player modes, with capability checks and explicit unavailable states. Cider's documented now-playing fields provide the mode readbacks without additional polling.
- Keep range adjustments visible while background observations arrive; after submission, show the adapter's result.
- Block further UI commands after an uncertain result until the player is observed again. Ignore a late command result after a newer player observation.
- Retry the failed collection page while keeping the inspector, loaded rows and exact-recording selection.

## Qualification

The [qualification ledger](../qualification.md) records the checks for this candidate. Contract tests, the synthetic MCP Apps host, real Apple API reads and interactive desktop-player receipts have separate scopes. The previous 0.6.0-rc.1 checkpoint passed real personal-library artist/album/song reads through the restarted connection, and its merged-main CI passed all seven jobs.

Actual expanded ChatGPT/Codex interaction remains pending because its app controller exposes no tab for the user's open view. Additional Windows/Cider transport and mixed-library/folder writes retain their separate live gates. No personal music write or playback change is made merely to fill a qualification row.
