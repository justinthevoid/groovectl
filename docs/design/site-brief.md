# Public website and README direction

The audience is an agent user deciding whether Groovectl can help, then a developer installing and operating it. Success is a clear first setup step, an appealing but truthful demonstration of curation, and a findable answer to platform/security questions. The existing cream, raspberry and olive studio identity remains recognizable.

## Direction contract

THESIS: A small independent record shop translated into a useful developer tool: tactile music artwork, generous editorial type and direct operating instructions. Show the listening journey and actual safeguards rather than a feature-card wall or invented listening statistics.

OWN-WORLD: Warm cream paper, dark ink, raspberry controls and olive supporting surfaces. Fraunces display lettering and DM Sans body text are self-hosted. A geometric groove mark works at favicon size; original cassette/sleeve artwork carries the music world.

STORY: The visitor recognizes Apple Music for agents, tries a short account-free brief, sees how recordings become a reviewed playlist, and follows setup for their real player. Limitations sit beside the relevant capability, not behind an empty promise of universal control.

FIRST VIEWPORT: Compact mark/wordmark navigation, a large two-line invitation at left with one setup action and one brief-builder link, and a generous original still life at right. On phones, text and actions precede the full artwork; no clipped columns. The signature interaction is a three-question brief composer with field locks and a surprise action.

FORM: Code-led editorial landing page extending the existing studio world. This provisional composition follows the user's overnight delegation; no design-choice roll, user-selected comp or permanent preference is claimed. Source context is captured here because the context loader did not return usable instructions.

QUALITY BAR: The actual rendered desktop/phone output and the landing-page source are the reference for this extension of the studio identity. Judge legible music artwork, inspectable generated briefs, visible keyboard focus, honest capability copy and a findable installation route. The independent reviewer retained the identity, editorial layout and original artwork; the two concrete UI defects were a clipped output region and insufficient focus contrast on its paper surface. No external competitor or approved visual comp is claimed.

## Decision and process record

The selected identity and code-led implementation were provisional decisions made under the user's explicit unattended development request. A surface concept roll was run only after the first review. Its suggested worlds were considered retrospectively and did not replace the incumbent studio identity. No user choice or telemetry choice event was submitted. The script returned an internal short key, not the documented public seed reference; that key is deliberately excluded from public source. The late roll cannot retroactively satisfy a pre-implementation workshop. This remains a disclosed process deviation, rather than fabricated design approval or a reason to replace working material.

The finish review is bounded to the website landing page and brief composer. Backend, MCP host integration and release qualification have their own checks.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
