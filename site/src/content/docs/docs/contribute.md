---
title: Contribute to Groovectl
---

Useful contributions improve a real listening or operating task. Extend a cohesive workflow before creating a tool for every endpoint or preference.

## Work locally

Use Node 24+ and the pinned Bun version. Install root dependencies with a frozen lockfile, then run check, build and test. The test script uses Node because the journal uses Node's built-in SQLite. Historical Python tests remain a migration regression reference.

The optional Swift helper has its own gate and tests. Do not run native builds in a shared environment without its resource allocation. Mac, Windows, Cider and API-only qualification are different tasks.

For site changes, use the independent site package. Check keyboard access, phone/desktop layouts, reduced motion, navigation and the actual production build. Keep original asset prompts/provenance and third-party licenses.

## Changes worth making

- More reliable identity and write verification, including missing/changed/partially accepted data.
- Creative sequencing, briefs and exports that preserve exact recordings and hard constraints.
- Qualified player controls grounded in documented APIs and real interactive sessions.
- Clearer onboarding, errors, accessibility and cross-agent compatibility.
- Reproducible packages, private operator deployment and source-bound release evidence.

Tests should exercise a meaningful behavior or failure mode. Never alter a contributor's real music preferences merely to qualify an endpoint. Keep credentials and personal fixtures out of commits.

## Before opening a pull request

Explain the user-visible problem, resulting behavior, checks actually run and remaining qualification gaps. Preserve legacy journals and installed plugin identity. Include focused regression coverage for a consequential behavior change. A green mock or static check is not live-service evidence.

See CONTRIBUTING.md, SECURITY.md, SUPPORT.md and CODE_OF_CONDUCT.md in the source repository. Public publication and deployment follow a separate reviewed release process.

The deployed static artifact includes [third-party notices](../../THIRD_PARTY_LICENSES.txt) and an [inclusive build-dependency inventory](../../dependency-inventory.json), including the self-hosted fonts' license files.
